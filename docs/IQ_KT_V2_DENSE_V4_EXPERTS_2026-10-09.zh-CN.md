# v2 稠密＋v4 专家＋IQ3_KT PLE 对照

2026-10-09，复用上一轮原 v4 的完整词表 logits，新增一组“v2 稠密＋v4 专家＋v4 IQ3_KT PLE”。
同样测试 128 个固定位置，并重复 8 个位置。原基准和其他旧组合没有重新推理。

这组相对原 v4 减少约 **1.6094 GiB GPU 权重载荷**。平均 NLL 为 **1.276728**，
比此前“v4 稠密＋v2 专家＋相同 IQ3 PLE”的 **1.266321** 高 0.010407，
且少节省约 1.1250 GiB 权重显存。按本轮综合样本和容量，尚未显示出更换稠密部分的优势；
工具/JSON 分项则更好，不能据此得出所有任务都更差的结论。

## 组合与来源

| 部分 | 新组合来源 |
| --- | --- |
| 稠密权重、387 个小投影、PLE key/value 投影 | v2 |
| 输出头、token embedding | v2 |
| 全部 144 个专家张量 | v4 |
| PLE 大表 `per_layer_token_embd.weight` | v4 IQ3_KT |

“保留 v4 专家”保留的是 v4 原有混合精度：112 个 IQ3_KT 张量和 32 个 IQ4_KT gate/up 张量。
后者位于第 0–5、38–47 层，没有把全部专家重新量化成 IQ4_KT。

本轮按整套 v2 稠密做对照，387 个小投影也取 v2。它们在运行时展开的大小与 v4 相同，
因此降低这些投影的源精度本身不节省显存。保留 v4 的这 387 个投影会是另一个组合，本轮未测。

候选 pack 普通复制 v2 的 dense/index/tokenizer 等文件，逐文件验证 SHA256；
专家索引逐角色显式指向原 v4 GGUF，核对全部 144 项的类型、形状、偏移和长度。
`--native`、输出头取 v2，两次 `--native-dense-gguf` 明确指定 v2 两分片，
`--ple-gguf` 单独指定 v4 的大表，避免自动发现把两个模型的稠密张量混在一起。

没有重新量化、校准或合成独立 GGUF。候选位于
`logs/iqkt-kld-20261009-v2dense-v4experts-01/pack/`，仍依赖原 v2/v4 分片。

## 质量指标

KLD 仍为 `KL(P_v4 || P_candidate)`，自然对数，越低越接近原 v4。
NLL 是对固定语料实际后继 token 的平均负对数似然，越低越好。
Top-1 是与 v4 的一致率，不是任务正确率。

以下三组都使用同一张 **v4 IQ3_KT PLE 大表**：

| 组合 | 平均 KLD | 中位 KLD | P95 KLD | 最大 KLD | Top-1 一致率 | 平均 NLL | 相对原 v4 的 GPU 权重节省 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 原 v4 稠密＋v4 专家，参考 | 0 | 0 | 0 | 0 | 100% | 1.238878 | 0 |
| 旧对照：v4 稠密＋v2 专家 | 0.031595 | 0.009411 | 0.065502 | 1.427432 | 92.1875%（118/128） | 1.266321 | 2.7344 GiB |
| 新对照：v2 稠密＋v4 专家 | 0.083597 | 0.035924 | 0.229604 | 2.262119 | 89.8438%（115/128） | 1.276728 | 1.6094 GiB |

作为额外背景，上一轮完整 v2 的平均 NLL 为 1.281316，当前部署的 IQ4 PLE lite 组合为
1.262176。这两组使用 v2 IQ4_KT PLE，不是上表中固定 PLE 的三组对照。

每类 32 个位置的平均 NLL：

| 语料 | 原 v4 | 旧对照：v4 稠密＋v2 专家 | 新对照：v2 稠密＋v4 专家 |
| --- | ---: | ---: | ---: |
| 中文 | 1.889617 | 1.900165 | 1.955694 |
| 英文 | 1.672961 | 1.708100 | 1.728996 |
| 代码 | 0.458025 | 0.477986 | 0.483232 |
| 工具调用与 JSON 文本 | 0.934909 | 0.979034 | 0.938992 |

工具/JSON 是本轮的例外：新组合 NLL 更低，尽管该分项相对 v4 的平均 KLD 更大。
这也说明 KLD 不能直接替代质量评价。本轮没有实际执行工具调用或运行生成代码。

## 显存与文件载荷

在同样 19＋29 分层下，减少的 GPU 权重载荷为：

| 项目 | 变化 |
| --- | ---: |
| 原生稠密矩阵 | 减少 1601.1719 MiB |
| 输出头 | 减少 146.8262 MiB |
| 展开后的 canonical 权重 | 增加 100.0000 MiB |
| 净减少 | 1647.9980 MiB，即 1.6094 GiB |
| 第一张 GPU / 第二张 GPU | 分别减少 0.5796 / 1.0297 GiB |

如果将选定张量合并为独立 GGUF，逻辑张量载荷比原 v4 少 **2.0356 GiB**。
这与 GPU 节省不同，因为部分低位宽张量在运行时会展开为较高精度。
数字不含 GGUF 元数据与对齐开销，也不表示本轮已释放对应磁盘空间。

自动专家缓存会使用腾出的显存，因此显卡空闲量不会必然增加 1.61 GiB。
实际日志显示，在相同测试设置下：

| 组合 | 第一张 GPU 驻留专家 | 第二张 GPU 驻留专家 | CPU 侧专家内存 |
| --- | ---: | ---: | ---: |
| 原 v4，复用上轮记录 | 9178 | 13436 | 约 3.76 GiB |
| 旧对照：v4 稠密＋v2 专家 | 9720 | 14292 | 约 1.02 GiB |
| 新对照：v2 稠密＋v4 专家 | 9482 | 13966 | 约 2.16 GiB |

新组合相对原 v4 多驻留 834 个专家。不同组合的 CPU/GPU 分工有差异，
因此跨模型的输出差异包含后端数值路径影响，不能完全归因于量化误差。

## 复现、验证与恢复

复用 `logs/iqkt-kld-20261009-quick-01/` 的 128 个位置、参考 logits 和四组旧统计。
新增输出在 `logs/iqkt-kld-20261009-v2dense-v4experts-01/`。
输入覆盖 8 篇合成文本，前缀 33–402 tokens；语料、tokenizer、输入序列、参考文件及
引擎 SHA256 复核通过。所有新 logits 都有完整的 248,320 个 FP32 值。

新组 136 次请求全部通过文件长度、有限值、SHA256 和输入长度检查，cached_tokens 均为 0。
8 次重复的 logits 逐字节一致，重复 KLD 为 0、Top-1 一致率为 100%。
旧四组结果保留在原目录；新汇总在单独目录中加入第五组，没有覆盖旧统计。

硬件沿用 RTX 2080 Ti 22 GiB＋RTX 4080 SUPER 约 32 GiB，系统 RAM 约 63.76 GiB。
同一个 `build-kt/pool-candidate/strata.exe`，SHA256：

```text
2947bb7c8f50e86cd1ae1b36aedb63527d3802c59800f8b90fc5ac72ef8c52c6
```

测试沿用 19＋29 分层，K8V8，resident KV 20480，prefill 2048，max-context 307200，
YaRN scale 1.171875，显存预留 1024/768 MiB。关闭 prompt cache、conversation pool、
MTP、suffix、lookup 和动态专家交换；用原样模板输入固定文本前缀。

最终恢复原 v4-lite 预设，仍使用 v2 IQ4_KT PLE，端口 8080，启动器 PID 26188。
健康检查 loaded=true，恢复后的文本请求成功，原 launcher argv/cwd、GPU 唤醒参数、
三个生产配置及 catalog 的哈希均保持一致。

这是 128 个短上下文位置的抽样检查，没有同源 BF16 参考、完整语料 PPL、长上下文或生成速度测试。
平均 NLL 的小差异不足以确认普遍能力排名；本轮也没有测试“v2 大稠密＋v4 的 387 个小投影”。
