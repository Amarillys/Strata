# IQ_KT 分支合并并部署上游 0.1.41

2026-10-08，将上游 `fb58e0dbc8399662c0e47c76578c6e878b14f6cf`（0.1.41）完整合入
`feat/iqkt-vulkan-vision`，合并提交为
[`97cc05b`](https://github.com/Amarillys/Strata/commit/97cc05bb405b46e919ebcbc0f825eb998dc61dcb)。
128 个上游提交无文本冲突；本地 KT、MTP 侧车、Vulkan 核显视觉和预设切换保留。

**同配置 A/B 没有测得整体吞吐提升。** 两种输入的 decode 均值分别变化 −2.0% / +1.5%；
未缓存 prefill 平均分别增加 0.422 / 0.368 秒。部署保留服务修复和长历史分词等更新，
不把其他硬件、其他多卡模式的上游性能数字当作本机收益。

## 升级 A/B：固定 21＋27、200K、K8V8

硬件为 i9-12900HK、64 GiB RAM、PCIe 3.0 ×8 的 2080 Ti 22 GiB、USB4 4080 SUPER 32 GiB。
新旧都运行 v4 IQ3_KT、21＋27、204,800 容量、K8V8、20,480 resident cells、2048 prefill、
前缀缓存 6、显存预留 1024 / 128 MiB、`--pcie-frac 0.5`、MTP 关闭、SSD direct PLE、核显视觉。

先等待线上请求结束，在仅本机访问的 18080 测试端口运行，避免其他会话打断缓存。
顺序为旧 A → 新 A → 旧 B → 新 B；每次独立加载后先预热，再测短输入首次/重复、
中输入首次/重复，各生成 256 token。每个版本、每种长度共 4 个 decode 样本、2 个未缓存 prefill 样本。

| HTTP 输入 token | 0.1.40.3 decode | 0.1.41 decode | 变化 | 旧未缓存 prefill | 新未缓存 prefill |
| ---: | ---: | ---: | ---: | ---: | ---: |
| 3,305 | 43.73 tok/s | 42.84 tok/s | −2.0% | 6.908 s | 7.330 s |
| 9,769 | 43.16 tok/s | 43.82 tok/s | +1.5% | 12.055 s | 12.423 s |

Decode 均值为总生成 token / 总 decode 秒数，不含 prefill。重复请求复用 3298 / 9762 token、
仅读入 7 个，因此不参与未缓存 prefill 均值。全部 16 个对应请求的输出文本按输入长度分别一致。
新版本中输入的两次未缓存 prefill 为 12.863 / 11.983 秒；样本较少，不应把均值差写成稳定比例。

新旧缓存均为 **9,142 + 13,824** 个专家，共 45,161 MiB；4080 全驻留、RAM 专家 3,117 MiB。
CUDA 图捕获时 4080 最低可用约 75 MiB，NVML 最低约 532 MiB，两种读数不是同一口径。

各轮使用相同的请求触发 GPU 唤醒。第二组 A/B 的请求区间遥测中，两版本 2080 核心均为
1500 MHz，显存出现 5000/6800 MHz；4080 核心 2100–2805 MHz、显存 11251 MHz。
区间包含 prefill，不是固定核心频率的 decode 专项实验；没有再次落入早期 405 MHz 显存状态。

## 新版 200K 长输入与持续输出

保持上述 21＋27 参数，完成以下测试后才部署：

| 请求 | 输入 / 输出 | 结果 |
| --- | --- | --- |
| 长输入 | 204,018 / 256 | Prefill 221.312 s（921.9 tok/s），decode 36.8 tok/s；三个分散位置的校验串正确 |
| 立即续聊 | 204,297 / 10 | 复用 204,273，只读入 24；prefill 0.373 s，正确返回最后一个校验串 |
| 持续输出 | 3,305 / 1,024 | Prefill 6.200 s，decode 40.6 tok/s |

测试期间最低 NVML 空闲约为 2080 的 1162 MiB、4080 的 532 MiB。
旧版历史长输入为 226.903 秒、36.5 tok/s，但本轮没有成对重跑旧版长输入；
这组新版结果主要用于验证容量、持续输出及缓存，不能据此声称长输入升级收益。

## 部署和保留的设置

版本 A/B 完成后，另按用户要求测试并采用 **22＋26、262,144 上下文、K8V8**。
两卡常驻专家为 **9,090 + 13,312**，4080 的全部专家仍在显存；RAM 专家为 **4.11 GiB**。
与上述同版本 21＋27 / 200K 相比，3,305 / 9,769-token 输入 decode 为
**41.43 / 41.86 tok/s**，少 **1.41 / 1.96 tok/s（3.3% / 4.5%）**。

实际 **261,618 输入＋384 输出**通过，prefill **320.104 秒**、decode **36.6 tok/s**；
三个检索串正确。立即续聊复用 **262,001** token、只读入 **23** 个，prefill **0.364 秒**，
总输入输出达到 **262,034 / 262,144**。长测 4080 的 NVML 最低空闲约 **1,518 MiB**，
图捕获后 CUDA 可用约 **1,059 MiB**。该配置在验证后恢复为日常 v4 预设。

这是独立的容量取舍，不计入上游版本提速；本轮未测试 21＋27 / 256K。
完整条件与逐次记录见 [256K 实验](../bench/results/2026-10-08-v4-256k/README.md)。

新版已在 `0.0.0.0:8080` 验证文本、Web、原模型别名和认证；无凭据 API 请求返回 401。
视觉仍在 Intel Iris Xe 的独立 Vulkan 进程，原来的启动器、密钥和 harness 地址保留。
最终分层与上下文以 [按需启动配置](IQ_KT_MODEL_SWITCH.zh-CN.md) 为准。

`STRATA_STAGE_PIN`、`STRATA_ROUTE_RESIDENT`、`STRATA_FS_SLOTS`、`STRATA_GDN_CHUNKED` 保持关闭。
Stage pin 的最终默认关闭修复随上游合入；没有改变专家路由来获得吞吐。
新无 P2P peer prefill 需要另一种多卡分工和 MMQ，本机 layer-split KT 路径不能直接套用。
具体适用性见 [合并前源码评估](IQ_KT_UPSTREAM_0.1.41_REVIEW.zh-CN.md)。

本机旧程序及校验清单保存在 `build-kt/pre-upstream-0.1.41/`。这是程序回退备份；
跨版本回退还需使用匹配的源文件和服务代码，不应只替换一个 EXE。
