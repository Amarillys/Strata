# v2、v4 与两种 v4-lite PLE 的 KLD 小样本测试

后续新增的“v2 稠密＋v4 专家＋IQ3_KT PLE”对照复用了本页参考 logits，见
[新增对照记录](IQ_KT_V2_DENSE_V4_EXPERTS_2026-10-09.zh-CN.md)；本页保留原四组结果。

2026-10-09，在相同的 128 个固定预测位置上，以 v4 为参考比较完整词表分布。
两种 v4-lite 的平均 KLD 都低于 v2。改用 v4 的 IQ3_KT PLE 后，平均 KLD 进一步下降，
但平均 NLL 比 IQ4_KT PLE 组合高 0.004146，Top-1 一致数少 2 个。
以缩减容量为目标，可以考虑 IQ3_KT PLE；这批样本尚不足以确定整体质量排名，
也不能确认 IQ4_KT PLE 的额外容量没有质量收益。

## 结果

KLD 为 `KL(P_v4 || P_test)`，使用自然对数，单位 nats。越低表示越接近 v4。
NLL 是对语料真实后继 token 的负对数似然，越低越好。Top-1 是与 v4 预测的一致率，
不是任务准确率。参考 v4 本身已经量化，因此 KLD 不能视为相对 BF16 的量化损失。

参考 v4 使用 IQ3_KT PLE；候选沿用同一张表，也可能保留参考相同的量化误差。
更高精度的 PLE 若纠正了其中一些误差，KLD 反而可能增加。因此不能仅凭本表的 KLD
或 Top-1 一致率选择质量最好的 PLE。现有 lite 的 IQ4 PLE 版虽然平均 KLD 更大，
平均 NLL 却略低，正说明这两种评价不能互相替代。

**完整 v4 稠密＋完整 v4 专家＋v2 IQ4_KT PLE 尚未测试。** 它同时保留 v4 的专家升级
和较高位宽的 PLE，是质量优先时值得单独验证的候选；本轮不能证明它最好，也不能排除
它优于当前四组。后续应比较相同语料的 NLL/PPL 和任务表现；获得同源 BF16 参考后，
再用相对 BF16 的 KLD 判断量化保真度。

| 权重组合 | PLE 大表 | 平均 KLD | 中位 KLD | P95 KLD | 最大 KLD | Top-1 一致率 | 平均 NLL |
| --- | --- | ---: | ---: | ---: | ---: | ---: | ---: |
| v4，参考 | v4 IQ3_KT | 0 | 0 | 0 | 0 | 100% | 1.238878 |
| v2 | v2 IQ4_KT | 0.080085 | 0.040418 | 0.219197 | 1.163650 | 89.0625%（114/128） | 1.281316 |
| v4-lite，当前部署的组合 | v2 IQ4_KT | 0.037340 | 0.009889 | 0.075528 | 1.247599 | 93.7500%（120/128） | 1.262176 |
| v4-lite，IQ3 PLE 对照 | v4 IQ3_KT | 0.031595 | 0.009411 | 0.065502 | 1.427432 | 92.1875%（118/128） | 1.266321 |

相对 v2，当前 IQ4 PLE 组合的平均 KLD 下降约 53.4%，IQ3 PLE 组合下降约 60.5%。
两个 lite 组合的平均 NLL 也低于 v2，但分项结果有不同方向，不能据此宣布所有任务都更强。
IQ3 PLE 相对 IQ4 PLE 的平均 KLD 下降约 15.4%，P95 也下降；最大 KLD 则更高。

IQ3 PLE 组合在中文、英文的样本 NLL 较低；IQ4 PLE 组合在代码、工具文本的样本 NLL 较低。
这次没有实际执行工具调用，也没有进行代码功能测试。

## 容量与组合

两个 lite 都使用 v4 稠密权重，包括 387 个高精度投影；144 个专家张量来自 v2。
PLE key/value 投影仍来自 v4。两个对照之间唯一的权重来源变化是
`per_layer_token_embd.weight` 大表：

| PLE 大表 | 逻辑张量载荷 |
| --- | ---: |
| v2 IQ4_KT | 25.0341 GiB |
| v4 IQ3_KT | 20.2657 GiB |
| IQ3 相对 IQ4 节省 | 4.7684 GiB |

若将选定张量合并成独立 GGUF，IQ3 PLE 组合的逻辑载荷比原 v4 少约 2.7344 GiB；
原 IQ4 PLE 组合则比 v4 多约 2.0340 GiB。当前仍然是引用源 GGUF 的混合加载，
这些数字不代表已释放磁盘空间。本轮没有生成新的合并 GGUF，也没有重新量化或校准。

## 方法与验证

- 8 篇固定合成文本，每篇 16 个位置；中文、英文、代码、工具调用与 JSON 各两篇。
  随机种子 20261009，预测前缀 33–402 tokens。选点在看到模型输出之前完成。
- 临时原样模板保留输入文本；对同一语料 token 序列取前缀，检查解码再编码完全一致。
  三个源预设的 vocab、merges、token_type 文件 SHA256 相同。每次 API 输入长度也核对通过。
- 当前原生 serve 路径的 `STRATA_DUMP_FIRST_LOGITS` 导出每个请求首个预测位置的完整 logits。
  每行 248,320 个 FP32；使用 FP64 稳定 log-softmax、温度 1 计算分布。
  没有使用截断的 top-k 概率，也没有比较自由生成后的不同上下文。
- 关闭测试实例的 prompt cache 和 conversation pool。全部请求的 cached_tokens 为 0。
  每模型额外重复 8 个位置：四组的重复 KLD 均为 0，Top-1 一致率均为 100%。
- 共 544 次采样请求；全部文件的长度、有限值检查通过，保存后的 SHA256 复核通过。

硬件为 RTX 2080 Ti 22 GiB、RTX 4080 SUPER 约 32 GiB，系统 RAM 约 63.76 GiB，
NVIDIA 驱动 610.88。四组使用同一个 `build-kt/pool-candidate/strata.exe`，SHA256：

```text
2947bb7c8f50e86cd1ae1b36aedb63527d3802c59800f8b90fc5ac72ef8c52c6
```

共同设置：19＋29 分层，K8V8，resident KV 20480，prefill 2048，max-context 307200，
YaRN scale 1.171875，显存预留 1024/768 MiB；MTP、suffix、lookup 和动态专家交换关闭。
这些是临时测试设置，原 v2、v4、v4-lite 配置文件没有改写。

专家驻留采用同一静态 profile 和自动显存容量。不同权重的 GPU/CPU 分工仍有差异：

| 组合 | 第一张 GPU 驻留专家 | 第二张 GPU 驻留专家 |
| --- | ---: | ---: |
| v4 | 9178 | 13436 |
| v2 | 9728 | 14848 |
| 两种 lite，均相同 | 9720 | 14292 |

因此跨 v2/v4/lite 的差异包含 CPU/GPU 数值路径的影响，不能完全归因于权重量化。
两种 PLE 对照的专家驻留数量相同，除 PLE 来源及测试文件名外，配置参数核对一致。

## 边界与恢复

这是短上下文、少量合成语料的抽样检查。没有同源 BF16/F16 主模型参考，没有完整语料 PPL、
长上下文质量或生成速度测试。JSON 中的 `exp_mean_sampled_nll` 仅是抽样 NLL 的指数，
不是标准数据集困惑度。KLD 较大也可能伴随真实 token 概率升高，不能将其直接解释为变差。

最终恢复到原 v4-lite 预设，仍使用 v2 IQ4_KT PLE，端口 8080；启动器 PID 为 26644。
健康检查 loaded=true，恢复后的文本请求成功，原 launcher argv/cwd、GPU 唤醒参数及三个
生产配置和 catalog 的哈希均保持一致。IQ3 PLE 仅作为本轮临时对照运行。

可复查的脚本、语料、逐位置统计及验证摘要见
[测试目录](../bench/results/2026-10-09-iqkt-kld/README.md)。原始 logits、内部配置与启动记录在
`logs/iqkt-kld-20261009-quick-01/`；含凭据的配置和启动器参数只保留在该本机目录。
