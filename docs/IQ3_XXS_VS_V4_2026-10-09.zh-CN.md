# IQ3_XXS 与 v4 IQ3_KT 本机性能对照

2026-10-09 实测。新下载的 **GSQ-RCO IQ3_XXS 在本机快约 54%–61%**，
且不需要 IQ3_KT 的兼容打包转换。两者使用同一 Strata 二进制、相同分层及运行参数。
本次结束后已恢复原 v4 服务和启动参数，原配置文件与 `strata-models.json` 的 SHA-256 均未改变。

测试文件为 `Qwen3.8-Flash-Next-GSQ-RCO-IQ3_XXS-00001-of-00002.gguf` 和
`Qwen3.8-Flash-Next-Uncensored-ik_llama-v4-IQ3_KT-00001-of-00002.gguf`，各自动读取第二分片。
IQ3_XXS 是 Strata 支持的 GSQ-RCO 格式，使用 `tools/iq_pack.py` 原生打包成功。

## 生成速度

单位 tok/s。每次生成 256 token；前三档各三轮，表中为中位数，128K 只有一轮。
所有测量请求均为新会话，实际前缀复用为 0。

| 实际输入 token | 每模型轮数 | v4 IQ3_KT | GSQ-RCO IQ3_XXS | IQ3_XXS 增幅 |
| ---: | ---: | ---: | ---: | ---: |
| 3,305 | 3 | 42.50 | 65.91 | +55.1% |
| 9,769 | 3 | 42.15 | 64.75 | +53.6% |
| 32,768 | 3 | 41.15 | 63.97 | +55.4% |
| 128,000 | 1 | 39.17 | 63.26 | +61.5% |

| 实际输入 token | v4 三轮范围 | IQ3_XXS 三轮范围 |
| ---: | ---: | ---: |
| 3,305 | 41.91–42.56 | 65.77–65.98 |
| 9,769 | 40.38–42.54 | 64.72–65.06 |
| 32,768 | 40.04–41.33 | 63.94–63.98 |
| 128,000 | 39.17–39.17 | 63.26–63.26 |

128K 的范围两端是同一个单次值，不表示重复测试。

## 显存与 RAM

| 项目 | v4 IQ3_KT | GSQ-RCO IQ3_XXS |
| --- | ---: | ---: |
| GGUF 两分片合计 | 72.52 GiB | 70.63 GiB |
| Routed expert 权重总量 | 47.15 GiB | 39.97 GiB |
| SSD 上的 PLE 表 | 20.27 GiB，IQ3_KT | 26.82 GiB，IQ4_NL |
| 2080 Ti 常驻专家 / 总数 | 9,069 / 11,264 | 11,264 / 11,264 |
| 4080 SUPER 常驻专家 / 总数 | 13,312 / 13,312 | 13,312 / 13,312 |
| 专家 RAM 补集（引擎 INFO） | 4,250 MiB | 0 MiB |
| 测试中两卡合计 NVML 峰值 | 51.42 GiB | 48.57 GiB |
| 测试中系统 RAM 使用峰值 | 27.28 GiB | 21.15 GiB |

IQ3_XXS 的全部 24,576 个专家驻留显存，两阶段均进入全驻留 CUDA graph；v4 只有后半段全驻留。
这是本机一个明确的执行路径差异，不能把全部增幅单独归因于某个量化算子。
文件名都是混合量化方案名称，GGUF 总大小也不能代表需要多少显存。

NVML 和系统 RAM 每 0.5 秒采样，属于观测峰值；系统 RAM 包含其他后台进程。
保留原 GPU 唤醒策略和动态核心频率，没有把功耗或频率设置成另一套测试配置。

## 条件与方法

- Windows Server 2025 Datacenter（build 26100）；i9-12900HK，14 核 / 20 线程，实际可见 RAM 63.76 GiB。
- RTX 2080 Ti 22 GiB＋RTX 4080 SUPER 32 GiB；驱动 610.88；原功耗上限 260 / 320 W。
  2080 Ti 连接为 PCIe 3.0 x8，4080 SUPER 沿用 USB4 外接；逐次链路状态在结果中保留。
  模型存于 KIOXIA EXCERIA PLUS G3 NVMe SSD。
- 同一 CUDA 引擎 0.1.41，源码 HEAD `546ceabf7702ed0f1fd96292b69cba1798ad0be6`，工作区已有本地修改。
  实际运行 `build-kt/pool-candidate/strata.exe`，SHA-256：
  `2947bb7c8f50e86cd1ae1b36aedb63527d3802c59800f8b90fc5ac72ef8c52c6`。
- 固定 split 22＋26、max-context 307200、K8V8 / `--kv int8`、KV resident 20480、prefill 2048、
  YaRN scale 1.171875、expert-cache auto、静态 `data/expert-profile.bin`、resident experts、
  GPU 预留 1024 / 128 MiB、pcie-frac 0.5、13 个 CPU pool workers、SSD direct PLE。
- **两者都关闭 MTP**，suffix draft 和 lookup chain 均为 0，adapt-every 0。
  保留 524288-token 会话池、四个槽、12288 MiB 快照预算、prompt-cache 2、prompt-cache-every 0。
  保留 Intel Iris Xe 视觉编码器和 `--vision`，本次请求均为纯文本。
- 固定 temperature 0、top-k 1、top-p 1、seed 424242、enable_thinking false。
  两份 tokenizer 的词表和 merges 哈希相同；模板文件虽不同，四组测试的渲染文本和 token 序列完全相同。
- 每种模型先用短输入预热一次，再依次测 3,305、9,769、32,768、128,000 token。
  每次使用新的会话身份并核对引擎 reused=0；保留已预热的专家与 PLE 行缓存，不清理操作系统文件缓存。
  同模型、同输入长度的三次输出哈希一致；两个模型的输出可以不同。
- 在 127.0.0.1:18080 隔离运行，使用原鉴权和 GPU 唤醒启动器，预设管理器加锁并 drain/unload。
  模型顺序为 v4 → IQ3_XXS → 恢复 v4。恢复后的短输入复测为 **42.48 tok/s**，
  对比初始中位数 42.50 tok/s；不是逐轮交错 A/B。
- 两次从启动到健康检查通过分别为 114.6 / 99.5 秒。
  只各测一次且未清理 OS 文件缓存，不能作为严格冷启动结论。IQ3_XXS 独立打包约 4 秒。

## 正确性及范围

32K 的三轮和 128K 的一轮都从约 20%、50%、85% 位置正确取回三个合成校验串，两种模型均通过。
128K 后立即续聊也均通过：

| 模型 | 输入 / 输出 token | 前缀复用 / 新读入 | 首字秒 | 纯 prefill 秒 |
| --- | ---: | ---: | ---: | ---: |
| v4 | 128,287 / 31 | 128,255 / 32 | 0.576 | 0.445 |
| IQ3_XXS | 128,287 / 31 | 128,255 / 32 | 0.479 | 0.331 |

这是合成检索和性能测试，未评估通用回答质量、中文、复杂代码、工具调用或视觉。
GSQ-RCO 与现有 Uncensored v4 并非同一文件的单一量化开关对照，不能凭速度断言能力高低。
也未测试 IQ3_XXS 的 MTP、其他分层、完整 300K 单会话或 512K 池压力；本次不是最大性能调优。
GGUF 检查覆盖分片、类型和 tensor 字节边界，记录了头部哈希，未计算整份模型 SHA-256。
